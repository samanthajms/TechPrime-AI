1 · The project in general opening questions

Explain your system in one minute.

TechPrime AI is an inventory, point-of-sale and online-store system for EasyPC One Oasis. A single database connects the counter, the stock room, the website and the office. A counter sale, an online order and a supplier delivery all update the same stock number immediately. Three AI features sit on top: demand and sales forecasting, the Primo chatbot, and a Build-a-PC recommender.

What problem does it solve?

Stock that drifts out of sync between counter and records, items running out without warning, no online channel, and buying decisions based on guesses. We answer with live stock, automatic low-stock alerts, an online store, and forecasts with reorder suggestions.

Who are the users?

Five roles. Clients (customers) shop online. Cashiers sell at the counter. Inventory Custodians manage products, stock-in and online orders. Retail Officers handle reports and forecasts. Admins handle accounts, logs and settings.

What makes it “AI”?

Three trained models. XGBoost forecasts demand and revenue. An SVM classifies what a chat message is asking for. A Random Forest ranks compatible PC parts. Each one was evaluated with held-out data (see the numbers above).

What is the scope? What is NOT included?

Included: one branch's inventory, POS, online orders (delivery via Lalamove or store pickup), reports, forecasts, chatbot and PC builder. Not included: multi-branch stock, a real payment gateway, accounting/payroll, and courier tracking integration.

What is new compared with existing systems?

Forecasts that turn into inventory actions (reorder point, order quantity). A chatbot that answers from live store data in Taglish. A PC builder that combines hard compatibility rules with a model trained on real customer builds. All on one shared stock database.

Did the client actually use or validate it?

The catalog is EasyPC's real item list (261 products, their SKUs and barcodes). Add your own evaluation or acceptance results here if you ran a user survey or client test.

Why the name “TechPrime AI”? Why “Primo”?

Answer from your team. Primo is the store's shopping assistant persona.

2 · Technology and architecture

What is your tech stack?

PHP 8.2 on Apache with vanilla JavaScript/CSS and a PostgreSQL database on Supabase. Python (scikit-learn, Flask) for the chatbot and PC models, and an XGBoost forecast service on Render. Gmail SMTP sends e-mails, and Chart.js draws the charts.

Your proposal said Next.js / FastAPI. Why PHP? trap

Plain PHP runs on XAMPP and simple hosting with no build step, which fit our timeline. We kept Python where it matters, for the ML. PostgreSQL was chosen because the POS needs real transactions and row locks.

Why PostgreSQL and not MySQL?

We needed reliable transactions, SELECT … FOR UPDATE row locks, RETURNING, CHECK constraints (stock ≥ 0) and a hosted, backed-up service (Supabase).

Why no framework (Laravel, React)?

The pages are server-rendered, which keeps them fast and simple to deploy with no build step. Shared helpers in includes/ give us the reuse a framework would.

How does the browser talk to the AI models?

It never does directly. The browser calls PHP, and PHP calls the Python services. That keeps API keys secret and lets PHP validate input, check the user's role and rate-limit.

backend/api/primo_chat.php · forecast_api.php
Where is it hosted?

Locally on XAMPP. For hosting, a Docker image (php:8.2-apache, Asia/Manila timezone). The database is on Supabase; Primo and the forecast service run on Render.

How do you keep passwords and API keys out of the code?

They live in a .env file or in server environment variables, loaded with phpdotenv, and never committed to Git.

Is it responsive / mobile-friendly?

Yes. Staff screens have a sidebar on desktop and a bottom tab bar on phones, and tables turn into cards on small screens. Buttons are at least 44 px, and status is shown with an icon and text, not colour alone.

3 · Security and access control

How are passwords stored?

As bcrypt hashes (password_hash). We never store or see the real password; login uses password_verify.

What stops brute-force login?

Three wrong passwords lock the account (is_locked), which is recorded in locked_accounts and the audit log. Only an Admin can unblock it.

login.php
Admin Settings has “max failed attempts”. Does it work? admit

The value is saved, but login currently uses a fixed 3. Connecting it is a one-line follow-up in login.php.

Can a cashier open the admin page by typing its URL?

No. Every page starts with checkRole(), which redirects to login. JSON endpoints check the session role and return 403.

What about SQL injection?

All queries use PDO prepared statements, so user input is sent as data, never as SQL.

And XSS?

Every value printed into HTML goes through h() (htmlspecialchars), so typed scripts show as text.

What is CSRF and how do you prevent it?

A forged form submitted from another site. Each form carries a random secret token stored in the session, and the server compares it with hash_equals before doing anything.

What if a staff member leaves the PC unattended?

After 15 minutes of inactivity the session ends; a 60-second countdown warning appears first. Background polling (stock alerts) doesn't count as activity.

How do you verify customer e-mails?

An activation link with a random 64-character token that expires in 24 hours. It works once (the token is deleted), and a resend option is offered.

Do you have two-factor authentication? admit

TOTP (Google Authenticator) code exists in the older API (backend/api/auth.php), but the main login page doesn't use it yet. Adding it for staff accounts is the next step.

Why does login say “Invalid email or password” for both cases?

So an attacker can't find out which e-mails have accounts.

How can you trace who did something?

logActivity() records the user, action, details (for example “stock 3 → 23”) and IP for logins, sales, stock-ins, orders, exports and settings changes. Admin sees it in Activity Logs.

Could someone read the database through Supabase's public API? deep

No. Row Level Security is on with no policies, so the public REST API returns nothing. Only our server's connection reads data.

What is session fixation and do you handle it? deep

An attacker plants a session ID before login. We call session_regenerate_id(true) on login, so the planted ID becomes useless.

4 · Cashier POS

Walk us through a POS sale.

Scan → the check digit is validated → the product is looked up → added to the cart. Then choose Cash, GCash, Maya or Card, complete the sale (one database transaction), and print the receipt with an invoice number like INV-20261023-000123.

How does the scanner work without clicking a field?

A USB scanner types like a very fast keyboard and ends with Enter. barcode_scanner.js detects keystrokes arriving milliseconds apart and treats them as a scan.

What if the barcode is misread?

The last digit is a check digit computed from the others (weights 1 and 3, then mod 10). One wrong digit breaks the check, and the scan is rejected in both the browser and the server.

Two cashiers sell the last item at the same time. What happens? trap

The sale locks the product rows (FOR UPDATE). The second sale waits, then sees stock 0 and gets “Not enough stock”. The update also requires stock >= qty, and the database forbids negative stock.

What if the cashier clicks “Complete sale” twice or Wi-Fi drops?

Each sale carries a unique ID (UUID, client_ref) created by the screen. A repeat request returns the original sale instead of charging twice. The UNIQUE constraint also covers two requests arriving at the same instant.

What if something fails halfway through a sale?

Everything is in one transaction: sale, items, stock deduction, stock movement and log. Any error rolls all of it back: “No changes were saved.”

Can someone change a price in the browser?

No. The server ignores browser prices and reads them from the database inside the transaction. If prices changed since the scan, the cashier is asked to review the new total.

How is VAT computed?

Prices include 12% VAT. VATable = total ÷ 1.12 (rounded to the centavo); VAT = total − VATable, so the two always add up exactly. Example: ₱3,450.00 → ₱3,080.36 + ₱369.64.

Why store money as centavos? deep

Decimal fractions like 0.1 aren't exact in floating point, so the POS works in whole centavos (₱1,234.50 = 123450) to keep totals and change exact.

What is a deadlock and how do you avoid it? deep

Two sales each waiting for a row the other locked. We always lock products in ID order, so the circular wait can't happen.

Can the cashier add stock?

No, by design. Stock-in belongs to the Inventory Custodian (separation of duties), so the person handling cash can't also adjust stock to hide shortages.

Is GCash/Maya/Card payment integrated? admit

At the counter the customer pays on their own app or terminal, and the cashier records the reference number (required). There is no direct API integration.

5 · Online store and orders

What are the order statuses?

To Pay → To Ship → To Receive (“With Courier”) → Completed, or Cancelled. Status only moves forward; Completed and Cancelled are final. Pickup orders skip To Ship.

When is stock deducted for online orders? trap

Stock is checked (with a row lock) when the order is placed, and deducted once, when the customer clicks “Item Received” or staff completes the order. Unpaid orders can still be cancelled, so deducting earlier would show items as sold out when they aren't. A stock_deducted flag guarantees it happens only once.

Then can two customers order the last item? trap

Both orders can be placed, because stock isn't reserved at order time. Completion deducts with stock >= qty, so the second completion is refused rather than going negative. A reservation step at payment is a possible improvement.

Is the online payment real? admit

No. It's a placeholder for the project; the page says so. “Pay Now” marks the order paid with a generated reference. A real gateway (for example PayMongo) would replace only that step.

Who can cancel, and when?

The customer can request it only while the order is unpaid and in To Pay, choosing a reason. The custodian approves it. Stock doesn't change because none was deducted.

What happens to a guest's cart after login?

It merges into the saved database cart (keeping the higher quantity for duplicates), so carts survive logout and login.

What stops a double order from a double-click?

A one-time checkout token: the second submit is refused.

How is delivery handled?

Delivery orders get a shipment record with carrier Lalamove; the custodian updates the status. Pickup orders become To Receive right after payment.

Can customers leave reviews?

One review per completed order: 1–5 stars, comment, tags, optional photos, and it can be anonymous. The custodian can reply.

How does the customer know what's happening?

Bell notifications at each step (placed, paid, accepted, completed, cancellation), each linking to the right order tab.

6 · Inventory, reports and admin

How do stock alerts work?

Out = 0, Critical = 1–5, Low = 6–15. After every stock change, the system compares the old and new level and notifies Admin, Retail Officer and Custodian only when the level changes (or stock recovers). The same alert isn't repeated within 24 hours.

Why fixed thresholds for all products? admit

It keeps the rule simple and clear for the store. A per-product reorder level, or using the forecast's reorder point, is the improvement.

How is a delivery from a supplier recorded?

Stock-in: scan, quantity (1–10,000), supplier (required) and reference number. It locks the row, adds the stock, and writes a stock_movements entry (before → after) plus an audit log line.

Where is your suppliers table? trap

There isn't one. A supplier is the product's brand, matched from the first word of the product name against the shop's brand list. Simple for this branch; a real suppliers table is future work.

What if a product has no barcode?

The custodian generates an in-store EAN-13: “21” + 10-digit product ID + check digit, and prints a label.

What counts as a sale in reports?

Completed online orders plus POS sales. Unpaid, in-transit and cancelled orders don't count. Reports read live data.

What reports can the Retail Officer produce?

Totals, transactions, units, average sale, sales by category, daily trend and a 12-month breakdown, with month-over-month and year-over-year % badges. Exports to CSV, Excel and PDF, and each export is logged.

What can the Admin do?

Create staff accounts, block/unblock/delete users, view all activity logs, set the password policy, and view alerts, forecasts and messages.

How is time handled? deep

Timestamps are stored in UTC and displayed in Asia/Manila time, so “today's sales” is correct wherever the server runs.

Is there internal communication?

Staff chat for Admin, Retail and Custodian: attachments, reactions, unsend, forward, pin and search, plus a floating widget on every staff page. Each action checks that the user is in that conversation.

7 · AI #1 · Forecasting (XGBoost)

What does the forecast predict?

Units per product (demand) and store revenue for 1, 2 or 3 months ahead. Each comes with a likely range, the trend, confidence, and inventory actions: days of stock left, safety stock, reorder point, stockout risk and a recommended order quantity.

What is XGBoost, simply?

Many small decision trees built one after another. Each new tree corrects the errors of the previous ones, and the forecast is the sum of all of them (“gradient boosting”). It works well on tabular sales data.

Why XGBoost and not ARIMA or linear regression? deep

Sales per product are irregular and depend on several factors (recent months, trend, category). Boosted trees handle many features and non-linear patterns without assuming a fixed curve, and they train fast on small tabular data.

What is a reorder point?

The stock level at which to order: average daily demand × supplier lead time + safety stock. Example: 2/day × 7 days + 6 = 20.

What is safety stock?

Extra units kept for unexpected demand or late deliveries, so the store doesn't run out while waiting for stock.

Why does the forecast sometimes load slowly?

The service is on Render's free tier, which sleeps when idle and can take about 50 seconds to wake. The proxy waits up to 75 seconds, and the screen asks the user to retry if it's still waking.

How is the forecast API protected?

Only Admin, Retail and Custodian can call it (403 for others). PHP adds the API key server-side, validates the horizon (1–3), category text and dates, and requires HTTPS.

How accurate is the forecast? admit

The screen shows each product's confidence and model reliability from the service's metrics. Quote the accuracy figure (MAE/MAPE/WAPE) from your forecast service's evaluation; it's in the forecast repository, not this codebase.

Where is the model code?

In a separate repository deployed to Render. This system uses it through forecast_api.php and displays it in includes/forecast_cards.php.

What if there is little sales history? trap

Forecasts are less reliable for new or rarely sold products; that's why the screen shows a confidence and a likely range, not just one number.

8 · AI #2 · Primo chatbot (TF-IDF + SVM)

How does Primo understand a question?

TF-IDF turns the text into numbers (words, word pairs and 3–5-letter chunks). An SVM then picks one of 16 intents with a confidence. PHP runs that intent's handler, which reads the live database.

What is TF-IDF?

Term frequency × inverse document frequency: words that are distinctive across all examples weigh more than common words like “the”.

What is an SVM?

A Support Vector Machine learns the boundaries that best separate the categories. We use an RBF kernel (C = 2.5, balanced classes) with probability outputs.

Why SVM and not a neural network or only ChatGPT? trap

With about 900 examples, an SVM is accurate, fast, explainable and runs on a free server. An LLM alone could invent prices or stock. Here the model only chooses the intent; the facts come from our database.

How does it handle Taglish and typos?

Character chunks: “magkano”, “mgkano” and “magkanoo” share most 3–5-letter pieces. The training data also has 102 Taglish/Filipino examples.

What if Primo is unsure?

If the top probability is below 0.32, it asks the shopper to rephrase instead of guessing, and saves the masked question so we can retrain on it.

How did you pick 0.32? deep

With tune_threshold.py on out-of-fold probabilities. Macro-F1 was almost flat from 0.10 to 0.32, so we took the highest threshold within 0.005 of the best. That's about 8% wrong answers and 9% rephrase requests.

How do you know the 83.8% is honest?

The 160-sentence hard test set was written before the new training data and is never trained on. Training rows that were too similar to a test sentence (cosine ≥ 0.80) were removed.

Then what is the LLM (Groq) for?

Only to rephrase our database sentence so it sounds friendlier, and for small talk about the shop. If any peso amount, product name or “N on hand” changes, the reply is rejected and the original sentence is used.

Can Primo answer off-topic questions (homework, love advice)?

No. Off-topic messages get a fixed “I'm only here for EasyPC” reply and are never sent to the LLM.

What about privacy (Data Privacy Act, RA 10173)?

E-mails and phone numbers are masked before anything goes to Groq or the unanswered log. That log has no user, session or IP and is deleted after 90 days. Chat history is deleted after 7 days, and the privacy policy page explains all of it.

Can someone spam Primo?

Rate limits: 15 messages per minute per browser and 60 per IP. Messages are capped at 400 characters, and CSRF is checked.

What are Primo's weak spots? admit

The “help” and “fallback” intents (4–6 out of 10 on the hard set). The test set was written by the same team, so the next round of data will come from real unanswered questions.

Can it answer “Will this GPU fit my case?”

Yes. Compatibility questions skip the SVM and use the same rules as Build a PC.

9 · AI #3 · Build a PC (rules + Random Forest)

How does it check compatibility?

It reads tags from product names and descriptions: socket, DDR type, form factor, NVMe/SATA, watts. Rules then check CPU socket = board socket, RAM type = board/CPU type, cooler socket, case ≥ board size and PSU ≥ estimated draw.

Then why do you need machine learning? trap

Rules only say what fits. Among compatible parts, the forest ranks what suits this purpose, budget and the rest of the build. On real customer builds it put the chosen part in the top 3 65% of the time, versus 57% for rules alone, 51% for price range and 40% for random.

What is a Random Forest?

60 decision trees, each trained on a random sample. Each one votes a “good fit” probability; we average them. A score ≥ 0.5 means a good fit, and the top 3 get the Recommended badge.

What features does it use?

23 features, including purpose, slot, price-tier gap versus the build, performance tier, balance, cooling margin, PSU headroom/rating and VRAM. The top ones are budget slack (19%), slot (14%), price-tier gap (13%) and performance tier (11%).

Where did the training data come from?

53,985 rule rows: random partial builds from the real catalog, labelled by expert rules for 5 purposes and several budgets. 739 real rows: saved builds, orders and POS sales, where the part the customer chose counts as good. Real rows are weighted 5×.

99% accuracy is suspicious. Is it overfitting? trap

It's cross-validated by build, so each score comes from builds the model never saw. It's high because most labels come from rules, which trees learn easily. On real rows alone it's about 47%, because only the one part the customer picked counts as “right”. That's why we report Hit@3 (65%) as the fair measure.

Does the model improve over time?

Yes. Every night at 02:00 it rebuilds the dataset from the database (read only) and retrains. The new model goes live only if the row count is ≥ 90% of the last run and accuracy is ≥ 0.90; otherwise the old model stays.

Why does PHP run the forest, not Python? deep

The trained trees are exported to forest.json, and PHP walks them directly. No extra server is needed, and recommendations work even if Python is down.

Can it recommend a part that leaves no option for another slot?

No. A “dead-end” check refuses any part that would leave a required part with no compatible item in stock.

What is “Build it for me”?

Given a purpose and budget, it fills each empty slot in order, using a budget share per slot and the best-scoring compatible part.

What if a product description is wrong? admit

Compatibility relies on product text, so bad names give bad tags. The fix is storing specs as proper product columns.

How is PSU wattage estimated?

CPU 65 W + board 40 W + GPU 180 W + RAM 10 W + storage 15 W for the rule check; the recommender also looks at PSU headroom and rating.

10 · Database, testing and deployment

What are your main tables?

users, products, orders / order_items / shipments, pos_sales / pos_sale_items, stock_movements (stock ledger), logs (audit), notifications, cart, wishlist, saved_builds, order_reviews, messages, site_settings.

Show us normalization / relationships.

Orders reference users; order_items reference orders and products; shipments reference orders; sale items reference sales. Sale items copy the name and price at the time of sale, on purpose, so old receipts never change.

How did you test the system?

Syntax checks on every PHP file. Database logic tested in transactions that are rolled back afterwards. Role access tested with logged-in requests per role. UI tested with automated headless-browser runs (including simulated scans) and screenshots at desktop, tablet and phone widths. ML models evaluated with cross-validation and held-out test sets.

Do you have unit tests? admit

No automated test suite. Testing was scripted and manual as described. The ML side has its own test scripts (test_intents.py, evaluate_cv.py).

What if the database is down?

Visitors see a branded “can't connect” page. Technical details go only to the server log.

What if an AI service is down?

Primo shows “temporarily unavailable”. Without Groq it still answers with plain database sentences. The forecast shows a “waking up, retry” message. Build a PC still filters with rules if the model file is missing.

Can it scale to more branches? trap

Not as is: stock is one number per product. Multi-branch needs a stock-per-branch table and a branch on each sale and order. The rest (roles, POS logic, models) carries over.

How are backups handled?

Supabase manages the hosted database and its backups. All schema changes are written as SQL migration files in database/.
